# ecg_dsp — fixed-point signal processing

Pure C11 (no hardware access, no globals, no malloc, no floating point).
Every module keeps its state in a caller-owned struct. Integer-only. The only
64-bit operations are multiplies (`__aeabi_lmul`) and a shift-subtract
`dsp_udiv64`, used once per beat or per summary. Per-sample code paths have
no runtime division. The code assumes `>>` on negative values is an
arithmetic shift (true for GCC and Clang).

Filter coefficients and delay constants are generated by
`tools/dsp_design/design_filters.py`, which also checks every spec against
the quantised coefficients. Its outputs are checked in:
`src/dsp_coefs.h` (private) and `include/dsp_delays.h` (public). The
`dsp_coefs_current` test fails if they are stale.

    python3 tools/dsp_design/design_filters.py            # verify + regenerate
    python3 tools/dsp_design/design_filters.py --check    # verify only
    python3 tools/dsp_design/design_filters.py --plot DIR # response plots

## Modules

| Header | Purpose |
|---|---|
| `dsp_decim.h` | 4 kHz ADC0 codes → 500 Hz stream: 95-tap FIR, 8:1 transposed polyphase |
| `dsp_ecg_disp.h` | Display path: 0.67 Hz Butterworth-2 HP → 50/60 Hz notch (Q 30) → 40 Hz LP → µV |
| `dsp_mains.h` | Goertzel bins at 50 and 60 Hz: pickup in µVpp, automatic notch choice |
| `dsp_qrs.h` | Pan–Tompkins R-peaks with sub-sample refinement, median-of-5 HR |
| `dsp_hrv.h` | Session statistics: beats, HR avg/min/max, SDNN, RMSSD |
| `dsp_ecg_mon.h` | Front-end state (railed / in range / stable), baseline, code statistics, wander, quality 0..4, auto-gain advisor |
| `dsp_ppg.h` | PPG frame reconstruction, bridging, band-pass, pulse foot, rate, PI |
| `dsp_ppg_ctrl.h` | DC-cancel DAC12, LED AGC, LED current limit, finger detection |
| `dsp_pat.h` | Pulse arrival time (R-peak to foot) on the shared timeline |
| `dsp_delays.h` | Generated group delays and timeline constants |
| `dsp_biquad.h` | Q30 DF-I biquad with fraction saving (used by all IIRs) |
| `ecg_dsp.h` | Umbrella include |

## Call order (fw/acq integration)

ECG, for each ADC0 DMA block of raw codes (any length):

1. `dsp_lead_push(raw, n, n_blank)` → `DSP_LEAD_EV_RAIL` / `_INRANGE` /
   `_STABLE` / `_UNSTABLE`. `n_blank`: how many leading samples were taken
   while FAST_RESTORE was held or within `DSP_LEAD_BLANK_MS` after it.
   - On INRANGE: `dsp_qrs_reset`, `dsp_disp_reset` (re-learn from here).
   - While railed: still decimate, but call `dsp_qrs_skip(q, n)` instead
     of `dsp_qrs_process` so that stream indices stay continuous.
   - Contact / session decisions (fw/acq, acq.h) use STABLE only; a rail is
     "recovering", not "thumbs off". If `dsp_lead_far_from_mid()` 500 ms
     after STABLE, pulse FAST_RESTORE once more.
2. `n = dsp_decim_push(raw, out)`. The output has room for
   `DSP_DECIM_MAX_OUT(len)` samples. These are the stream samples (×8 units).
3. Pass the same 500 Hz samples to `dsp_mains_push`, `dsp_wander_push`,
   `dsp_qrs_process` and `dsp_disp_process` (µV for `UI_TRACE_ECG`).
4. For each beat: `dsp_hrv_add_beat(rr_ms)`, `dsp_gain_beat(amp)`,
   `dsp_pat_add_r(index, frac)`, then `STREAM_EV_R_PEAK` with `index` and
   `hr_bpm`.
5. Every 0.5 s (after `dsp_mains_push` returns true): if the notch setting
   is AUTO and `dsp_mains_auto_hz()` is not 0, call `dsp_disp_set_notch()`.
   Every 10–1000 ms: `dsp_gain_tick(elapsed, dsp_lead_take_clip())`.
   Every second: `dsp_ecg_quality()`.
6. Gain or mid changes take effect between records: re-init `decim`, `disp`,
   `mains`, `wander`, `gain` (they take the gain and mid at init) and reset
   `qrs`.

PPG, for each frame (100 Hz):

1. `dsp_ppg_process(frame, dac12_in_effect, in_flags, &out, &pulse)`.
   `in_flags` = `DSP_PPG_IN_DAC_STEP` / `_LED_STEP` for the first frame
   after a change; use them on any frames that may still be settling.
   `out.coarse` and `out.fine` go to the stream (set stream flag bit0/1 when
   `in_flags` is non-zero). `out.disp` feeds `UI_TRACE_PPG`.
2. `dsp_finger_update(out.coarse, tia_on)` → stream bit2 (no finger).
3. On a pulse: `dsp_pat_add_foot(pulse.frame, pulse.frac_q8)`, then
   `STREAM_EV_PULSE` with `dsp_pat_foot_ecg_index()`, `pulse_bpm`, the next
   `dsp_pat_pop()` result (ms) and `pi_permille`.
4. Control: every 100–250 ms, `dsp_agc_step(mean tia_on of undisturbed
   frames)`. When the LED code changes, also set DAC12 to
   `dsp_ppg_dcc_predict(...)` so that PPG_HI does not rail. About once per
   second: `dsp_ppg_take_avg()` → `dsp_ppg_dcc_update()`. The LED limit is
   `dsp_led_max_code(led_limit_ma(setting))`. Apply changes between frames
   and flag the next frame.

## Units and sign conventions

| Quantity | Unit |
|---|---|
| ECG stream sample | (code − mid) × 8, int16, saturated (`STREAM_ECG_SCALE`) |
| ECG display output | µV, input-referred: s × 805.7 / (8 × gain) |
| Mains pickup, wander | µVpp, input-referred |
| R-peak | stream index (500 Hz, from `dsp_qrs_init`) + `frac_q8`/256 |
| QRS `amp` | peak-to-peak in the clean signal, stream units (full scale 32768) |
| PPG coarse | tia_on − tia_dark, ADC codes (0.806 nA photocurrent per code) |
| PPG fine | **−photocurrent** in TIA_OUT/10 codes (80.6 pA): `hi_on − 11·dac12 + 10·tia_dark` (or `hi_on − hi_dark` when hi_dark is in range). More blood → less light → fine goes **up**, so the systolic upstroke points upward in the stream and on the display. The stream sends int16 modulo 2^16. |
| PPG `disp` | band-passed fine (0.5–8 Hz), fine units, saturated int16 |
| Foot | input frame index (from `dsp_ppg_init`) + `frac_q8`/256. Frame k's on-sample is at k·10 ms + 9.95 ms |
| PI | permille (0.1 %): AC (fine units) × 100 / coarse |
| PAT | µs, from `dsp_pat_pop` |

## Group delays and timeline (`dsp_delays.h`, all removed in the outputs)

| Path | Delay | Constant |
|---|---|---|
| Decimator FIR (95 taps, linear phase) | 47 raw samples = 11.75 ms. Stream sample m = raw time 8m − 40, i.e. t = 2000·m − 10000 µs | `DSP_DECIM_DELAY_RAW`, `DSP_ECG_STREAM_T0_US` |
| Analog ECG chain (0.32 + 0.48 Hz HP, 159 + 339 Hz LP) | 974 µs (R-peak shift of a σ = 10 ms Gaussian) | `DSP_ECG_ANALOG_DELAY_US` |
| QRS clean LP (Bessel-4 + 50/60 Hz nulls) | 5.57 samples (1426/256), flat within 0.08 samples over 1–20 Hz | `DSP_QRS_CLEAN_DELAY_Q8` |
| QRS band-pass after the clean LP | 16.85 samples at 10 Hz (QRS localisation only) | `DSP_QRS_BP_DELAY` |
| QRS reporting latency | 80 ms after the MWI peak. Measured 208–267 ms after the R-peak (300 ms bound). Search-back beats are later. | `DSP_QRS_LATENCY_MAX` |
| ECG display path | 3.38 samples (6.8 ms) at 10 Hz (drawing only) | `DSP_DISP_DELAY_Q8` |
| PPG FIR LP (21 taps, linear phase) | 10 frames | `DSP_PPG_LP_DELAY` |
| PPG centred dark mean (15 frames) | 7 frames | `DSP_PPG_DARK_DELAY` |
| PPG foot total | 17 frames. Pulses are reported about 0.2–0.3 s after the foot. | `DSP_PPG_FOOT_DELAY` |
| PPG analog (TIA 10 µs + 2nd stage 11 µs) | 21 µs | `DSP_PPG_ANALOG_DELAY_US` |

`t_R = 2000·index + frac·2000/256 + DSP_ECG_STREAM_T0_US − DSP_ECG_ANALOG_DELAY_US`,
`t_foot = 10000·frame + frac·10000/256 + 9950 − DSP_PPG_ANALOG_DELAY_US` (µs).
Both assume the ECG and PPG timers start from the same event (ecg-fw.md).

## Code size (arm-none-eabi-gcc 14.2, `-Os`, Cortex-M0+)

10 068 bytes of text in total, 0 data, 0 bss. Largest objects: `qrs.c` 2.9 KB,
`ppg.c` 2.8 KB, `ecg_mon.c` 0.8 KB, `hrv.c` 0.6 KB, `decim.c` 0.6 KB. libgcc
helpers used: `__aeabi_lmul`, `__aeabi_llsr`, and 32-bit `__aeabi_(u)idiv`
(per beat, pulse, window or control call only).

## Rules worth knowing

- **Front-end state:** a raw code < 205 or ≥ 3891 (5 % of either rail) is a
  rail sample. **Railed:** more than 80 rail samples (20 ms) in a run; gaps
  shorter than 20 ms (mains riding on the rail) do not end the run, 20 ms
  continuously in range does (INRANGE). Shorter runs are clipping.
  **Stable:** in range continuously for `DSP_LEAD_STABLE_MS` (500 ms, one
  tau of U5's coupling). Blanked samples (FAST_RESTORE) pause every count.
  The state starts railed with an empty run.
- **Quality 0..4:** 0 without contact or while railed, or when more than 5 % of the last
  second's raw samples were on the rail. Otherwise start from 4 and
  subtract:
  - 1 for any rail sample;
  - 1 if mains > 100 µVpp, or 2 if > 400 µVpp;
  - 1 if the 2 s baseline range is > 500 µV, or 2 if > 1500 µV;
  - 1 if there has been no beat for 3 s, or the RR spread is over 30 % (not
    while settling).

  The result is clamped to 1..4 while in contact.
- **HRV outliers:** an RR interval counts as NN if it is between 273 and
  2000 ms and within ±20 % of the median of the last 5 raw intervals.
  Rejected intervals break the RMSSD chain. HR min and max are taken from the
  median-of-5 NN rate.
- **Auto-gain:** at 558×, recommend UP after a full 5 s window with at
  least 3 beats, every QRS under 8192 units (25 % of range, 1.48 mV) and no
  clipping. At 1098×, recommend DOWN on 3 clip events within a 5 s window,
  or on a QRS over 90 % of range. The advice latches until re-init.
- **Mains auto-select:** a frequency is dominant when its amplitude is at
  least 5 µVpp and at least 2× the other. While undecided, the first
  dominant 0.5 s window decides. A switch later needs 2 consecutive windows.
- **AGC:** below 0.6 V, step up 25 %. Above 2.8 V, step down 20 %. Once
  triggered, keep stepping until TIA_OUT(on) is inside 1.5–2.0 V. A step of
  1.25× is smaller than the window (1.40× in photocurrent), so the loop
  cannot hunt. DCC dead band: PPG_HI(on) within ±1024 codes of mid.
- **Finger:** present when coarse > 250 codes for 300 ms. Absent when
  coarse < 150 codes, or TIA_OUT(on) ≥ 4040 (ambient overload), for 300 ms.
- **PAT pairing:** each foot is paired with the latest R-peak before it,
  but only once a later R-peak has been seen. Valid PATs are 100–500 ms, and
  the R–R interval that contains the foot must be ≤ 1.5× the previous one.

## Test results (host, `ctest`; also clean under clang ASan + UBSan)

- **Decimator:** passband 0.5–150 Hz −0.084..+0.002 dB (0.086 dB p-p).
  Attenuation: 46.3 dB at 250 Hz, 52.6 dB at 350 Hz, 46.5 dB at 1 kHz, and
  at least 46.0 dB everywhere from 250 to 2000 Hz. Delay 47.00 raw samples.
  DC exact. Saturates without wrap. Bit-identical for block sizes 1, 3, 7,
  8, 13, 64 and random.
- **Display:**
  - Gain at 10 Hz 0.998. −2.99 dB at 0.67 Hz and at 40 Hz; −14 dB at 0.3 Hz (breathing wander). −29 dB at 150 Hz.
  - Notch depth at 50 and 60 Hz > 200 dB (exact zeros). −0.04 dB at the
    other mains frequency.
  - Off-centre rejection: 18.5 dB at 50.1 Hz and 12.7 dB at 50.2 Hz.
  - Settling: 1 mV step to < 1 % in 1.45 s; 50 Hz onset to < 1 % in 0.76 s.
  - Zero and constant input decay to exactly 0 (no limit cycles). One hour
    of full-scale abuse recovers to 0.
- **Mains:** 40/200/1000 µVpp measured 44–46 / 200 / 996–999 µVpp at both
  gains. ECG-only floor ≤ 8 µVpp.
- **QRS** (analog chain simulated, 16 cases of 120 s, 3298 beats):
  - Cases: clean 40–200 bpm, 0.2–2 mV, 1098×, tall T (T = R), 50/60 Hz up to
    1.8 mVpp, wander 0.8 mV, EMG 60 µV rms, ectopics.
  - 0 FN, 0 FP: Se = PPV = 100 % in every case.
  - R-peak timing error: max 0.52 ms clean, 2.95 ms noisy; mean −0.2..−0.3 ms.
  - HR within ±1 bpm of the true median-of-5 in every case.
  - Weak beats (40 % amplitude every 7th): 103/103 found, 15 by search-back.
  - Lead-off for 3 s: no false beats, first beat 2.8 s after contact, then
    34/34.
- **HRV** (300 s through the chain): SDNN 45 vs 44.66 ms true, RMSSD 58 vs
  57.75 ms, HR 68 vs 68.2 bpm.
- **PPG** (closed loop with DCC and AGC, flicker and forced DAC12/LED steps):
  - DAC12 steps of ±120 codes: the stream fine value jumps by at most 15
    codes (noise level). Without the formula the jump would be 1320 codes.
  - LED step: 7 units on the display bridged, 851 units unflagged.
  - Foot timing error (spec cases, PI 1–3 %, 45–120 bpm, 0.1 nA noise): max
    2.72 ms, σ 0.36–1.21 ms.
  - Stress at PI 1 % with 0.3 nA noise: max 4.2 ms. At PI 0.5 % with 0.6 nA:
    max 20 ms.
  - Pulse rate within ±1 bpm in every compared beat. PI within 15 %.
- **PAT** (both full chains): error against the true per-beat PAT is
  ≤ 2.4 ms max. 72 bpm/250 ms: mean +0.48 ms. 100/180: +1.01 ms. 55/320:
  −0.01 ms. 130/150: +1.56 ms.

## Limitations and notes

- **Notch width.** At Q 30 the notch rejects only 12–14 dB at ±0.2 Hz from
  nominal mains. This is the trade for its 0.2 s settling. The QRS detector
  does not depend on it: it uses exact 50 and 60 Hz nulls.
- **PPG foot noise.** Foot timing is noise-limited at low PI. σ is about
  1.2 ms at PI 1 % and grows as 1/PI. The `hi_dark` rail forces the dark term
  to come from the 12-bit `tia_dark` ×10. The 15-frame centred mean only
  partly recovers this. Updating DAC12 per phase by DMA (ecg-fw.md) would
  remove the issue.
- **PPG foot bias.** The tangent foot comes from the 11.4 Hz linear-phase
  signal. Its bias is −0.5 ms on the test pulse shape, and larger for
  sharper real upstrokes. At high heart rates, overlapping pulses move the
  true tangent foot later (+2.6 ms at 130 bpm); this is real, not an error.
- **Sanitizers.** The system GCC on the dev box has no ASan/UBSan runtimes,
  so the root CMake builds without them. For the sanitized run use
  `-DCMAKE_C_COMPILER=clang`.
